# 같이가개 개발 로드맵

마지막 갱신: 2026-10-27 · 저장소: https://github.com/bins-hub/gatigagae

## 개발·배포 원칙
- 모든 개발 작업은 기존 `main` 및 `gh-pages` 복구 브랜치를 만든 뒤 시작합니다.
- `main`은 소스, `gh-pages`는 빌드 결과. `gh-pages`에 컴파일되지 않은 소스를 올리지 않습니다.
- 테스트 → 빌드 → 검증 → 배포 → 실제 URL 확인을 순서대로 진행합니다. 실패 시 공개 배포를 중단합니다.
- 업체 **직접 검증 0곳**을 유지합니다. 외부 공개자료의 이용 조건을 현재 입장 가능 보증으로 바꾸지 않습니다.
- 확인되지 않은 장소를 이미지·후기·위치 좌표·통화기록으로 꾸미지 않습니다.
- `noindex,nofollow`, `robots.txt: Disallow: /`는 업체 직접 검증·운영정보·정책 등 조건 충족 전까지 유지합니다.
- 외부 API 키, 개인정보, 도메인 연결, 사업자정보, 운영자 승인, 비용·마케팅 계정 연결은 사용자 확인이 필요한 작업입니다.

## 자동화 / 수동 작업
- GitHub CI는 커밋 후 자동 실행되나 사용자 명령이 끝난 뒤 ChatGPT가 자체적으로 다음 개발을 계속 실행하지는 않습니다.
- [x] `.github/workflows/deploy-pages.yml`에 **GitHub Actions 방식 자동 배포**를 안전하게 준비. 설정 전에는 스킵되고 기존 사이트는 `gh-pages`로 운영합니다.
- [ ] 최초 한 번 운영자가 Pages 게시 원본을 `GitHub Actions`로 바꾸고 `PAGES_ACTIONS_ENABLED=true` 저장 후 새 워크플로 실행·검증. 정확한 방법은 `docs/AUTO_DEPLOY.md`에 기록했습니다.
- 현재 Pages 설정은 **branch: gh-pages**, 정적 출력을 해당 브랜치에 업데이트해야 실제 발행됩니다.
- GitHub Actions의 `GITHUB_TOKEN`으로 밀어 넣은 브랜치 커밋은 Pages의 새 빌드를 자동 트리거하지 않을 수 있습니다. 따라서 자동 배포로 간주하지 말고 Pages 배포 상태와 공개 페이지까지 검증합니다.
- 명령어: `같이가개 계속 개발` → 이 문서·실제 GitHub 상태 확인 → 다음 가능한 미완료 작업 개발 → 백업·테스트·배포·검증.
